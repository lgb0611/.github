# 말하면 받아쓰기 · 예시 답안 단어 비교 (2.10.0)

## 왜 추가했나

2.9.0까지 무료 모드에서는 앱이 내가 말한 영어를 글자로 알 수 없었습니다. 말한 뒤 직접 타이핑하거나 Windows 받아쓰기(`Windows + H`)를 따로 켜야 했고, 자가 점검에서는 예시 답안을 눈으로 한 줄씩 비교해야 했습니다. 말하기 연습에서 가장 자주 반복하는 단계라서 이 부분을 줄였습니다.

## 사용법

1. **스피킹 연습** 화면의 녹음 칸에서 **말하는 동안 영어로 받아쓰기**를 체크합니다. 처음 한 번 전송 안내가 나옵니다.
2. **● 녹음 시작**을 누르고 말합니다. 말한 영어가 **실시간 받아쓰기** 칸에 나타납니다.
3. **■ 녹음 마침**을 누르면 받아쓴 영어가 **내가 실제로 말한 문장** 입력란에 들어갑니다.
4. 녹음을 다시 들으며 잘못 들린 곳만 고치고 확인란을 체크합니다.
5. **말한 답변 자가 점검**을 누르면 예시 답안에 단어 표시가 붙습니다.
   - 초록: 내 답에도 있는 단어
   - 주황: 내 답에는 없던 단어
   - "예시 답안 단어 N개 중 M개를 같은 순서로 말했어요"
   - **목표 표현 찾기**: `came up with` → `come up with`처럼 시제가 바뀌거나, `ask her out` → `ask someone out`처럼 자리표시어(`someone`, `one's`, `~`, `A/B`)가 있는 표현도 찾습니다.

## 알아둘 점

- **전송:** Chrome은 Google, Edge는 Microsoft의 음성 인식 서비스로 녹음 중 말소리를 보내 글자로 바꿉니다. 요금은 없고 앱의 유료 API도 쓰지 않습니다. 받아쓰기를 켜면 왼쪽 안내 문구가 "받아쓰기 켜짐 · 녹음 중 말소리를 브라우저 음성 서비스로 전송"으로 바뀝니다. 끄면 이전처럼 녹음은 이 브라우저에만 남습니다.
- **기본값은 꺼짐**입니다. 켠 상태는 학습 기록과 함께 저장되고, 설정을 백업·가져오기 할 때도 유지됩니다.
- **지원 브라우저:** Chrome, Edge. Firefox처럼 음성 인식이 없는 브라우저에서는 체크박스가 비활성화되고 안내 문구가 나옵니다. `OPEN_ME.html`을 파일로 직접 열면 브라우저가 받아쓰기를 막을 수 있습니다. 그때는 `start_free_windows.bat`으로 실행하세요.
- **인식 결과는 틀릴 수 있습니다.** 음성 인식은 잘못 듣거나, 틀리게 말한 문법을 올바르게 고쳐 적을 수 있습니다. 그래서 확인란은 자동으로 체크하지 않습니다. 원래 인식 결과는 **처음 인식된 원문 보기**와 제출 기록의 "음성인식 원본"에 따로 남습니다.
- **이미 입력한 글은 덮어쓰지 않습니다.** 녹음 중에 직접 입력한 내용이 있으면 받아쓰기 결과는 원문 보기에만 둡니다.
- **받아쓰기 오류가 나도 녹음은 계속됩니다.** 마이크 권한·인터넷·기기 문제로 받아쓰기가 멈추면 이유를 표시하고, 녹음과 자가 점검은 그대로 사용할 수 있습니다.
- **단어 비교는 점수가 아닙니다.** 같은 뜻을 다른 표현으로 말하면 비율이 낮게 나옵니다. `I'm`↔`I am`, `can't`↔`cannot`, `thirty`↔`30`, `stopped`↔`stop`은 같은 단어로 봅니다. 발음은 평가하지 않습니다. 복습 평가는 이전처럼 직접 선택합니다.
- **문장 카드(유튜브 자막·PDF 문장)**는 목표 표현 찾기를 하지 않고, 위의 단어 비교만 보여 줍니다. 새 상황 문단에서 원래 문장을 그대로 말할 필요가 없기 때문입니다.

## 검증 범위

| 범위 | 방법 | 결과 |
|---|---|---|
| 단어 비교·표현 찾기·받아쓰기 제어 | Node 단위 테스트 (`tests/test_speech_check.js`) | 13개 통과 |
| 화면 흐름 | jsdom + 모의 음성 인식 (`tests/test_ui.cjs` 끝부분) | 8개 통과 |
| 기존 기능 회귀 | 전체 Node 테스트 | `docs/validation_results.json` 참고 |
| 실제 브라우저 화면 | Chromium 141에서 PC(1280px)·휴대폰(390px) 폭으로 녹음 → 받아쓰기 → 자가 점검 | 페이지 오류 없음, 가로 넘침 없음 |
| 실제 Chromium 음성 인식 | 가짜 마이크 환경에서 실제 `webkitSpeechRecognition` 실행 | 인식 서비스가 마이크를 쓰지 못한다는 오류(`audio-capture`) 표시, 녹음은 계속됨 |

실제 사람 목소리로 Google·Microsoft 음성 인식이 글자를 돌려주는 과정은 이 환경에서 확인하지 못했습니다. 인식 결과를 받은 뒤의 화면 흐름은 모의 인식 결과로만 검사했습니다.

Chrome의 기기 내 음성 인식(`SpeechRecognition.available`, `processLocally`)은 사용하지 않습니다. 검사 중 헤드리스 Chromium 141에서 `available()`을 호출하자 페이지가 멈췄습니다. 일반 Chromium 141에서는 멈추지 않고 `downloadable`(아직 설치 안 됨)을 돌려줬지만, 페이지가 멈추는 위험을 피하려고 호출하지 않습니다.
