# Astra Speaking Lab v2 검증·업그레이드 보고서

## 판단

원본은 제출 전 교정하지 않는 녹음 흐름, 실제 발화 인용 확인, 원자료와 새 예문의 구분을 이미 갖추고 있었다. 개선이 가장 필요한 부분은 **학습 성과를 기록하는 정확성, 복습으로 이어지는 흐름, 기록·비동기 처리의 안정성**이었다. 이 부분을 수정하고 학습 기능을 추가했다. 앱의 학습 효과나 AI 교정 정확도에 수치 점수를 부여하지 않았다.

## 학습 콘텐츠

핵심 카드의 한글 단문·영어 예문 **100쌍**, 기존 연습 문단 **42쌍**을 읽고 뜻·주체·시제·표현 사용을 대조했다. 새로 추가한 **30개**는 가브리엘 8~10강의 각 핵심 표현을 다른 짧은 상황에서 사용하는 문제다.

두 문단을 수정했다.

- `g07_story_2`: 모호한 ‘끄지도 않은 알람’을 ‘설정한 기억도 없는 알람’으로 바꾸고 영어에도 해당 의미를 반영.
- `kpop_story_2`: 한글의 ‘우리는’이라는 흐름과 맞도록 마지막 영어 문장의 주체를 `we`로 수정.

100개의 핵심 단문과 72개의 문맥 문제를 사용할 수 있다. 자동 추출 항목 2,774개를 모두 언어적으로 검증한 것은 아니다. 원본 이미지·PDF·DOCX 전체와 추출 텍스트를 다시 전수 대조하지 않았다. `sources/`의 원자료 바이트는 수정하지 않았다.

## 학습 설계의 근거와 한계

이미 배운 표현도 다시 떠올리게 하는 설계는 반복 인출 연구를 참고했다. 단순 재학습과 구분해 실제로 회상하는 기회를 남기는 것이 핵심이다. 다만 해당 연구를 이 앱 사용자에게 그대로 적용한 효과 크기는 계산하지 않았다. [Karpicke & Roediger, 2008](https://learninglab.psych.purdue.edu/downloads/2008/2008_Karpicke_Roediger_Science.pdf)

교정 후 같은 내용을 다시 말하고 다른 상황으로 확장하도록 구성했다. 말하기 과제 반복의 근거로 확인한 de Jong & Perfetti의 연구는 ESL 학습자 24명의 4·3·2분 말하기 훈련을 다뤘다. 이 앱은 그 실험을 복제하지 않았으며, 단문 연습이나 제안한 학습 시간이 같은 결과를 낸다고 주장하지 않는다. [de Jong & Perfetti, 2011](https://research.vu.nl/en/publications/fluency-training-in-the-esl-classroom-an-experimental-study-of-fl/)

다음은 연구에서 입증한 보편적 최적값이 아니라 앱의 운영 규칙이다.

- 15~20분 제안, 한 묶음 새 표현 최대 3개·전체 최대 8개.
- 최근 24시간 영어 노출 시 독립 성공에서 제외.
- 1·3·7·14·30일 간격과 독립 성공 3회 등의 표시 기준.
- 다른 과제 ID를 처음 제출한 사실을 새 상황 판정의 단서로 사용.

성과 확인은 같은 날 빨리 따라 한 횟수보다 **다음 복습 시점에 힌트 없이 사용한 표현**, **다른 문맥에서 적절히 쓴 표현**, **반복되는 실제 오류가 줄었는지**를 보도록 했다. 현재 자가평가와 AI 판단은 여전히 틀릴 수 있다.

## 검증 결과

| 범위 | 방법 | 결과 |
|---|---|---|
| 원본 서버 기준선 | 원본 제공 pytest 20개 실행 | 20개 통과 |
| 최종 서버/API·자료 | 실제 FastAPI ASGI 요청, 인용·형식·크기·설정·보안·API 모의 응답 | **40개 통과** |
| 최종 복습·백업 로직 | Node.js 테스트, 날짜 이동·이른 반복·힌트·전이·백업·문제 가져오기 | **27개 통과** |
| 최종 화면 상호작용 | jsdom, 저장소·권한 대기·녹음 종료·세션 진행·복사·오류 노트 | **28개 통과** |
| 로컬 서버 실행 | Linux에서 launch.py를 실행하고 실제 HTTP로 HTML·설정 확인 | 통과 |
| HTML 빌드 | 동일 소스로 서버용·단독 HTML 재생성 및 일치 확인 | 통과 |
| 원자료 보존 | 입력 ZIP과 sources/ 파일의 SHA-256 대조 | 32개 파일 동일 확인 |

**최종 자동 테스트 합계 95개**. 원본 기준선 20개는 최종 서버 테스트 40개에 포함하므로 합계에 중복 가산하지 않았다. 테스트 이름·완료 결과는 `validation_results.json`과 `node_test_results.txt`, `python_test_results.txt`에 있다.

서버 검증은 실제 HTTP/ASGI 처리이지만 OpenAI 응답은 통제된 모의 데이터다. UI 검증은 **DOM 시뮬레이션**이며 실제 브라우저·실제 마이크의 통과 기록이 아니다. 브라우저별 렌더링·모바일 넘침·화면 확대·기기 합성음에 관한 시각적 통과 판정은 하지 않았다. Browser(control-browser) 스킬이 요구하는 전용 브라우저 실행 도구가 이 환경에 제공되지 않아 실제 화면 검증을 진행하지 못했다.

Windows/macOS 실행과 실제 마이크, 실제 유료 API 호출은 미검증이다. 새 가상환경 설치 로그에는 의존성 설치와 서버 시작이 나타났지만, 최초 실행 시험의 최종 결과 수집은 환경의 네트워크 승인 취소로 중단되어 전체 과정 통과로 판정하지 않았다. Linux의 준비된 의존성에서 서버 실행은 별도로 확인했다.

AI의 의미·문법 판단 정확도나 발음 점수를 검증했다고 해석하면 안 된다. 최종 교정문 일치 검사는 모델이 문장별 수정 자체에 새 사실을 넣는 모든 경우를 잡아낼 수 없다.

## API 확인

기본 모델은 원본의 `gpt-6-astra`를 유지했다. 공식 문서의 검토 강도 지원을 확인해 기본값을 `medium`으로 하고 low·medium·high 선택을 추가했다. 더 강한 설정의 교정 품질이 더 좋다는 실측 비교는 수행하지 않았다. [모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)

`gpt-transcribe`의 `languages[]` 요청과 구조화 출력 스키마 형식을 확인했다. 실제 계정의 모델 권한·잔액·네트워크·현재 서비스 동작은 API 요청 시 확인해야 한다. [파일 음성인식](https://developers.openai.com/api/docs/guides/speech-to-text), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs)

## 사용 시 확인할 부분

기존 기록은 먼저 내보낸 뒤 v2에서 가져온다. 녹음은 새로고침 전에 저장한다. 첫날 새 표현을 본 뒤 성공해도 독립 인출 횟수가 늘지 않는 것은 새 규칙에 따른 정상 동작이다. API 키가 없을 때 ChatGPT로 복사한 교정은 자동으로 앱 기록에 수입되지 않으므로 자가평가를 직접 저장한다.

`docs/v1_archive/`에는 이전 설명서·시험 결과·화면 캡처를 보존했다. v2의 새로운 화면 검증 자료로 사용하지 않았다.
